# Songfolio

Multilingual song lyrics catalog (Greek + English) at `songfolio.live`: a Go
REST API with PostgreSQL, a Next.js (App Router) frontend, and authentication
through Prelude Auth. The repository, Go module and web package are still named
`lyrics`. `README.md` covers setup, Prelude configuration, the API, the catalog
import and deployment.

## Layout

```
backend/
  cmd/api, cmd/migrate, cmd/import-songs   entry points
  internal/api        HTTP handlers and router (server.go)
  internal/store      pgx queries (hand-written)
  internal/auth       Prelude token verification
  internal/prelude    Prelude Management API client
  internal/httpx      handler/error envelope, client IP
  internal/imaging    avatar normalization
  internal/testutil   test DB, token issuer, fixtures
  migrations/         SQL migrations (embedded via embed.go)
web/
  src/app/            App Router routes: (auth), (shell), (shell)/(menu), admin
  src/routes/         screen components rendered by each page.tsx
  src/components/     shared UI
  src/lib/            helpers; navigation.tsx is the routing seam
  src/api/            client.ts (fetch) and hooks.ts (React Query)
  src/auth/           auth provider and Prelude SDK session
  src/test/           MSW handlers, TestProviders, TestRouter, TestApp
  e2e/                Playwright
  icons/              icon sources and generator (make icons)
.do/app.yaml, scripts/deploy-do.sh   DigitalOcean App Platform
```

## Commands

```bash
make up            # PostgreSQL on host port 5433
make seed          # migrate + sample songs
make api           # API on :8080
make web           # web app on :5173
make mobile        # web app reachable from a phone on the LAN
make format        # gofmt + Biome (rewrites files)
make check         # lint + test, both stacks; keep it clean
make test-backend  # Go tests (starts the DB first)
make test-web      # vitest with coverage, then every story in Chromium
make clean         # stop services and delete the DB volume
make icons         # regenerate icons from web/icons/*.svg
```

## Gotchas

- Go integration tests **skip** without a database. Run them via
  `make test-backend`, not bare `go test`.
- Applied migrations don't re-run when edited. Run `make clean` before trusting
  tests after changing an existing migration. Test a backfill by hand against a
  database with existing rows.
- A worktree has no `.env`. Export the main checkout's values before `make web`.
- `.env` holds live credentials and is gitignored. Never copy secrets into
  tracked files.
- Mirrored logic must change in both places: `app_slugify` ↔ `store.Slugify`,
  `extractVideoId` ↔ `parseYouTubeURL`, the inline theme and font-size scripts
  in `app/layout.tsx` ↔ `lib/theme.ts` and `lib/fontSize.ts`, and the "first
  recording" ORDER BY in `attachRelations` ↔ `refresh_songs_denorm`.
- `songs.slug` and the song's `youtube_*`/`release_year`/`credits_text` columns
  are written only by triggers. Don't write them from Go.
- Every API route naming a song must accept both slug and UUID. In the frontend,
  build and parse song addresses only through `lib/listContext.ts`.
- A person's or genre's catalog page is addressed only through `personPageHref`
  and `genrePageHref` (`lib/browse.ts`): the route's canonical and the sitemap
  both use them, and `sitemap.test.ts` checks that they agree.
- The API omits `song_count` when it is zero. Read an absent count as 0, not as
  "not counted" or malformed.
- The sitemap is all or nothing: any failed read or malformed row yields `/`
  alone, because a partial sitemap looks like a smaller catalog.
- Never read `localStorage` or `window` during render. Use
  `lib/useStoredState.ts`.
- No `metadata.title` or `generateMetadata` title; titles come from `PageTitle`.
  No `loading.tsx` or Suspense above pages.
- Lyrics are user input: search snippets use `⟦…⟧` sentinels and JSON-LD goes
  through `scriptBody`. Never render user text as HTML.
- In a story or spec, wait for what a `lazy()` chunk renders by first
  `await import()`ing the module the `lazy` names, not with a longer `findBy`.
  The dev server compiles the chunk on first request, which under load outlasts
  `findBy`'s one second.
- A new `NEXT_PUBLIC_` variable goes in `Makefile` (web and mobile),
  `docker-compose.yml`, `web/Dockerfile` and `scripts/deploy-do.sh`.
- `web/AGENTS.md` and `web/CLAUDE.md` are regenerated by `next dev`. Leave them
  as they are.
